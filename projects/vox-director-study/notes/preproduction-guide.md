# 模型无关前期导演台使用指南

## 它解决什么

你可以没有 Atlas Cloud，也可以没有 Vox Director 使用的任何视频模型。这个导演台只负责在生成之前把内容整理成明确、可检查、可交接的数据：

```text
上游结构样例
  → 主题与画幅
  → Beats / Shots 人工编辑
  → 关键帧提示 + 运动提示
  → 资产清单 + 人工关卡
  → provider-neutral JSON
  → 交给你的图片模型、视频模型或另一个 Agent
```

它不会上传文件，不会调用 API，也不会因为修改主题就假装自动完成了改稿。

## 操作步骤

1. 第一次使用可直接打开 `?demo=dunhuang#prep` 查看完整的敦煌 30 秒示范；也可在“准备台”选择其他结构样例。
2. 填写自己的主题，选择画幅、目标总时长和生成路线。
3. 写下自己的执行模型名称，仅用于交接标记，不会发起调用。
4. 点击“应用并刷新准备包”，把目标总时长按比例分配到全部 shots。
5. 敦煌示范可直接点击顶部“复制全部 6 镜头”；若要逐个生成，展开 shot 后点击“复制本镜头”。复制文本已经合并首帧说明、画幅、时长、画面、运动和负向提示。
6. 如需修改内容，再在“镜头编辑”调整标题、旁白、scene、still prompt 和 motion prompt；黑色直接输入卡会同步更新。
7. 在“资产清单”检查当前路线还缺什么，并勾选事实、权利、文字、主体、连续性和音频关卡。
8. 只有接 API 或自动化执行器时才需要“交接 JSON”；手动使用视频模型不必复制 JSON。

## 直接演示：Codex 图片 + 外部视频模型

敦煌示范已经把图片阶段实际跑完：`media/dunhuang/` 中有 6 张 9:16 关键帧，页面每个 shot 都会显示对应图片，资产清单显示 `6/6` READY。手动生成视频时，只需上传图片并点击“复制本镜头”；不需要自己从多个字段拼提示词。

可直接复制的逐镜头提示与统一负向约束见 [敦煌视频调度提示](dunhuang-video-dispatch.md)。视频生成完成后按 `B01-S01.mp4` 至 `B03-S02.mp4` 命名，即可与当前交接包逐镜头对齐。

## 四种生成路线

| 路线 | 适合情况 | 最小输入 |
| --- | --- | --- |
| 文本 → 视频 | 没有图片模型，视频模型可以直接理解镜头描述 | scene、motion、时长、画幅 |
| 关键帧 → 视频 | 可以先生成或设计静帧，希望构图更稳定 | still prompt、参考图、motion、时长、画幅 |
| 首尾帧 → 视频 | 需要明确镜头终点或可控转场 | 首帧、尾帧、motion、时长、画幅 |
| 参考素材 → 视频 | 人物、产品或品牌主体需要持续出现 | 参考图、scene、motion、时长、画幅 |

## 如何接入自己的模型

导出文件使用 `research-lab.preproduction-pack/v1`。每个 shot 都包含一个 `model_task`：

```json
{
  "model_task": {
    "route": "image-to-video",
    "target_model": "你的模型名称",
    "required_inputs": ["still_prompt", "reference_image", "motion_prompt", "duration", "aspect"],
    "optional_inputs": ["negative_prompt", "seed", "end_frame"],
    "missing_required": ["reference_image"]
  }
}
```

接入时只需要写一层 Adapter，把这些通用字段映射到实际模型的参数名。执行前必须拒绝 `missing_required` 非空的任务；任务完成后建议把供应商任务 ID、模型版本、费用、耗时、输出路径和人工审核结果写回自己的运行账本。

## 推荐的前期完成标准

- 每个 beat 的叙事作用明确，旁白可以在分配时长内说完。
- 每个 shot 只保留一个主要镜头运动，元素运动与镜头运动分开描述。
- 中文、数字、字幕和 Logo 不烘焙进概率性画面，改由后期叠加。
- 人物/产品参考素材已经确认权利，主体连续性有人工复核人。
- 事实、数字、引用和视觉隐喻已经分开记录。
- 交接 JSON 中没有 `missing_required`，人工放行关卡均有明确负责人。
