# Vox Director 研究报告

## 一句话结论

`vox-director` 已经从“创作规则说明”跨进“可运行媒体生产编排”：它用一个 `beats.json` 串起叙事、视觉、图片、视频、声音和 ffmpeg 后期，并通过两个人工审批点控制昂贵生成。它的强项是把创意 SOP 变成可执行阶段；弱项是事实、测试、跨平台、质量指标、成本追踪和生产治理。

因此，它比纯 Prompt Skill 更接近自动制片厂，但仍是实验性生产套件，不是可以无人值守的大规模视频平台。

即使我们没有 Atlas Cloud 或上游采用的视频模型，仍可复用它最有价值的前半程：`beats.json`、逐镜头 still/motion prompt、资产需求和人工审批。本研究新增了模型无关前期导演台，把 4 份上游样例规范为 17 beats / 26 shots，并导出 `research-lab.preproduction-pack/v1` 供其他模型 Adapter 使用；整个准备过程不调用外部 API。

## 研究问题与判断标准

研究问题：这个仓库是否真的包含从输入到成片的运行时？它已有的样例证明了什么？适合什么任务？如果要成为我们的能力，应优先扩展什么？

判断分成五层：

1. **输入层**：是否覆盖主题、真人视频和单张照片，而不是只有一个 Prompt 模板。
2. **创意层**：叙事、风格、镜头和运动是否形成明确协议。
3. **执行层**：是否真实调用图片、视频、音频服务并处理异步失败。
4. **后期层**：是否包含时间线、字幕、混音和 MP4 导出。
5. **生产层**：是否具备测试、质量阈值、来源、成本、隐私和跨平台能力。

会推翻当前结论的证据包括：源码实际只有文档没有执行器；随库视频无法读取；三个模式只是 README 宣传而没有实现；或仓库已经存在未被发现的测试与生产治理层。

## 它与 Hand-Drawn Video Prompts 到底差在哪里

| 层 | Hand-Drawn Video Prompts | Vox Director |
| --- | --- | --- |
| 输入 | 已写好的中文口播 | 主题、真人口播视频、单张人物/产品照 |
| 创意输出 | 分镜、隐喻、图片 Prompt、运动 Prompt | 叙事弧、主题、shots、Prompt、模型参数 |
| 模型调用 | 不包含 | 图片、视频、TTS、音乐、ASR |
| 运行状态 | 不包含 | `beats.json` 持续写回 URL、路径、时长和 Prompt |
| 后期 | 依赖宿主另行实现 | ffmpeg/Pillow 字幕、混音、拼接、水印 |
| 最终交付 | 生产说明包 | 尝试直接交付 `final.mp4` |

最短结论是：前者告诉你“这条片怎么做”，后者继续“调用设备把这条片做出来”。

## 能力和原理

### 1. B-roll：主题到成片

宿主 Agent 先从 14 种叙事弧中选择结构，把主题写成 `beats.json`。每个 beat 包含旁白、标题、背景、情绪和一个或多个 shot；shot 再包含景别、镜头运动、元素运动和时长。

随后执行：

```text
主题
→ beat-layer.md 选择叙事结构
→ 用户确认分镜
→ style_bakeoff.py 生成多种风格
→ 用户选择主题
→ keyframes.py 生成拼贴海报
→ clips.py 让海报运动
→ audio.py 生成旁白和音乐
→ assemble.py 生成 final.mp4
```

它的核心创意判断是“风格在图片阶段诞生，运动在视频阶段追加”。图片 Prompt 强调独立纸片、清晰边缘、投影、报纸、套印和标题；视频 Prompt 只描述一个运镜和丰富的内部元素运动，并用约束保护平面结构和文字。

### 2. A-roll：真人口播改造

`asr_beats.py` 从原视频提取音频并获取词级时间戳，按句末和停顿切成不超过约 9.5 秒的片段。`aroll_clips.py` 将每段交给视频编辑模型；主模型失败的片段再走备用模型。`aroll_assemble.py` 丢弃模型返回的声音，把原视频对应片段的音频重新混入。

这可以保证使用原声和原时间范围，但“原声回填”本身不能证明生成后的嘴部动作逐帧同步。仓库没有捆绑 A-roll 成片，也没有口型偏差指标，所以演示把它标为“已实现管线、未由随库样例独立证明”。

### 3. C-roll：单图锚定

`croll_keyframes.py` 把人物或产品照片上传给图片编辑模型，并按 portrait/product 写入不同的冻结约束。人物模式锁定脸、头发与服装，产品模式锁定形状、材质和标签；随后复用标准视频、声音和合成管线。

这里的“pixel-faithful”仍然是 Prompt 目标，不是像素级算法。更稳妥的生产实现应对脸、Logo 和文字做后验检测。

### 4. 本地逐元素动画

高级路径先用 `extract_elements.py` 把海报裁成透明图层，再由 `motion.py` 使用位置、缩放、旋转、透明度和 easing 生成帧。优点是确定、可复现且不经过视频内容过滤；代价是框选、清理残边和关键帧布局仍然高度手工。

### 5. 生成式与确定性的分工

```text
生成式：叙事草稿、图片、视频、TTS、音乐
人工：分镜确认、风格选择、失败镜头复核
确定性：状态文件、ASR 切点、时间线、字幕、水印、混音、导出
```

这是整个仓库最值得复用的架构原则。生成模型负责开放创意，ffmpeg/Pillow 负责必须可重复的时间和图层操作。

## 已有样例证明了什么

固定提交包含四支视频：

| 文件 | 时长 | 分辨率 | 编码 | 证据含义 |
| --- | ---: | ---: | --- | --- |
| `showcase-tang.mp4` | 29.98s | 1280×720 | H.264 + AAC | 16:9 中文历史拼贴成片 |
| `showcase-money.mp4` | 58.93s | 720×1280 | H.264 + AAC | 9:16 六 beat / 十二 shot 成片 |
| `showcase-football.mp4` | 62.88s | 1280×720 | H.264 + AAC | 横屏体育历史样例 |
| `showcase-silicon-valley.mp4` | 59.11s | 1280×720 | H.264 + AAC | 横屏科技历史样例 |

四支视频总时长约 210.9 秒，证明仓库至少保存了真实可播放输出。四份 `beats.json` 则进一步展示了 Prompt、URL、镜头、旁白和本地路径如何贯穿阶段。

不过这些样例没有 prediction ID、完整 API 响应、成本、随机种子、失败日志或自动质量结果。因此它们能证明“流程产出过视频”，不能证明任何用户、任何时间、任何模型版本都能严格复现相同结果。

README 还展示墨西哥街头美食，但固定提交只保存缩略图，没有相应 MP4；演示明确把它标成 poster-only。

## 工程成熟度

### 已经做得好的部分

- 每个阶段是一份单独 Python 脚本，`beats.json` 是共享中间协议。
- Provider 抽象让阶段脚本不直接耦合 Atlas Cloud 客户端。
- 图片/视频任务可并行提交，并对失败或卡住任务局部重交。
- 已生成的 URL 会被跳过，支持粗粒度断点恢复。
- 画幅不匹配会停下来要求人工确认。
- A-roll 按 beat 路由备用模型，不需要重做整条片。
- ffmpeg 处理了画幅归一、短片段减速、字幕、水印、音乐闪避和尾段裁切。

### 当前边界

1. Provider 注册表只有 Atlas Cloud 一个实现。
2. Skill 要求 Agent 手工查询实时模型列表，API 客户端没有自动检查。
3. 重新提交可能产生新的计费任务，没有预算上限或幂等键。
4. 上游没有自动测试、CI 或 JSON Schema。
5. `atlas_cloud.py` 硬编码 `/usr/bin/curl`，Windows 无法直接运行。
6. 文档 Schema 支持 `3:4`，B-roll `assemble.py` 的输出分辨率表没有 `3:4`。
7. 标题在图片模型中烘焙，没有 OCR 或确定性文字层。
8. 没有事实、来源、更正、隐私和授权工作流。

## 使用场景

### 适合

- 知识、历史、财经概念和产品原理的 15–60 秒解释视频。
- 品牌故事、产品照片、创始人或个人 IP 的固定视觉栏目。
- 已有真人口播，希望用背景和贴纸提升信息密度。
- 实拍 B-roll 不足，但抽象概念可以被海报化的内容。
- 小团队在人工审批下快速试片和比较视觉方向。

### 不适合直接使用

- 精确 UI、金额、合同、药品说明和复杂数据图表。
- 没有编辑审核的热点新闻、医疗或金融建议。
- 长篇人物连续性、复杂表演和电影级空间调度。
- 必须一次生成准确 Logo、中文标题与包装文字的商业素材。
- 要求严格 SLA、预算上限和失败自动恢复的批量生产。

## 可扩展方向

### P0：先让结果可信、可追踪

1. 增加事实与来源 Schema，把引用、事实、观点和隐喻拆开。
2. 图片生成无文字底图，标题、Logo、日期和数字走确定性后期与 OCR。
3. 移除 macOS/Linux 路径假设，加入 Windows 环境探测和配置校验。
4. 保存 prediction ID、模型版本、参数、耗时、费用、失败原因和最终 take。
5. 为 `beats.json` 建 JSON Schema，并给每个阶段增加输入/输出契约测试。

### P1：进入稳定生产编排

1. 增加 OpenAI、Google、Kling、Runway、Seedance 或本地后端适配器。
2. 加入缓存、幂等、预算上限、任务队列、审批状态和局部重跑。
3. 自动检查 OCR、人物相似度、Logo、闪烁、黑帧、音量、静音和口型偏差。
4. 保存素材哈希和阶段 manifest，防止 URL 失效后无法追溯。

### P2：让编辑能够控制而不是只会重抽

1. 制作 beats 时间线编辑器和多 take 对比界面。
2. 自动分割拼贴元素、推断层级和建议关键帧。
3. 建立品牌色板、字体、角色 Bible、允许/禁止素材和领域隐喻库。

## 对我们的意义

`hand-drawn-video-prompts` 让我们看到创作规则怎样变成可复用 Prompt Skill；`vox-director` 继续展示这些规则怎样变成一个会调用工具、等待任务和组装媒体的 Agent 工作流。

它对 Research Lab 有三层价值：

1. **比较单位**：`beats.json` 可以成为不同视频方案共享的中间协议，用同一口播比较分镜、Prompt、模型输出和成本。
2. **架构参考**：Provider、阶段脚本、人机审批、局部重跑和确定性后期都值得吸收。
3. **研究升级**：后续不再只检查 Prompt 是否完整，还可以检查生成失败率、耗时、成本、OCR、闪烁、音频和最终视频。

不应该照搬的是“Vox 风格”本身。更可持续的方向是把视觉主题替换成我们自己的科技新闻、财经或教育栏目系统，并保留可验证的结构化生产链。

最终建议：**研究和 Fork 价值高；直接生产采用需要先工程化。**

## 本机直接运行条件

2026-08-29 检查结果：

- Python 3.10、Pillow、ffmpeg、ffprobe、Windows `curl.exe` 已存在；
- `ATLASCLOUD_API_KEY` 未配置；
- `python3` 命令不存在；
- `/usr/bin/curl` 路径不存在。

因此当前可以阅读、审计、播放样例和运行静态后期工具，但不能直接照 README 执行完整 Atlas Cloud 生成。修复跨平台路径并由用户自行配置 API Key 后，才适合进行付费生成实验。

## 许可、安全与隐私

MIT License 允许使用和修改仓库代码与文档，但不自动授予人物肖像、声音、Logo、品牌素材、音乐和外部模型输出的商业权利。A-roll、C-roll 和声音克隆会把视频、照片或参考音频上传到外部服务，真实生产必须增加知情同意、保留策略、地域和供应商条款审查。

使用“Vox-style”作为描述不代表 Vox 官方合作。商业产品更适合建立自己的视觉语言，避免造成来源或品牌关联误解。

## 局限

1. 本研究没有 Atlas Cloud API Key，也没有授权产生付费生成费用，因此没有从零复跑上游成片。
2. A-roll 与 C-roll 只验证源码路径，没有随库视频可用于独立质量复核。
3. 媒体检查覆盖格式、时长、尺寸和等候浏览器播放，没有逐帧视觉模型评分。
4. 上游模型 ID、价格和服务条款会变化；结论只对应固定提交和 2026-08-29 的环境。
5. GitHub raw 视频播放依赖网络；演示的本地海报与元数据构成可读降级。
