截图转页面是低频入口，Agent 闭环才是研究价值。

它没有训练专用截图模型，而是把多模态模型、文件工具、素材裁剪和浏览器截图反馈连接成一个视觉前端复刻闭环。

01 / 能力

它交付的是可运行原型，
不是完整生产系统。

输入端接受视觉参考和修改历史；输出端以单个 index.html 为中心，追求快速预览与迭代。

03 / 价值

它压缩的是视觉沟通成本，
不是整个软件工程。

最大增量

从静态参考到可执行讨论对象

设计稿、截图或录屏不再停留在“请照着做”，而是快速变成能点击、能截图、能继续修改的前端原型。

传统分析 → 切图 → 编码 → 调样式 → 对齐
Agent参考 → 原型 → 人工验收 → 工程化
01

用户价值

降低产品、设计和开发之间的视觉翻译成本。

02

工程价值

提供 provider、工具运行时、文件状态与流式事件的参考实现。

03

研究价值

适合比较视觉反馈、素材策略、模型质量、成本和失败类型。

04 / 使用场景

先判断交付目标，再决定是否使用。

筛选场景，区分“适合做原型”和“可以直接上线”这两个完全不同的问题。

正在显示全部 9 个场景

适合

营销页与活动页

视觉主导、状态有限，原型可以快速进入人工校准。

适合

内部概念验证

把想法变成可点击页面，用于评审、销售或融资沟通。

适合

旧页面视觉恢复

没有源文件时先建立可运行基线，再逐步工程化。

适合

研究演示初稿

为 Research Lab 的证据与内容快速搭建视觉载体。

谨慎

多页面产品

共享组件、路由和状态可能重复，需要后续重构。

谨慎

长页面与高密度界面

上下文、视觉一致性和模型成本会快速上升。

谨慎

品牌与敏感界面

需要单独处理版权、素材许可、隐私和外部 API 风险。

不适合

复杂生产系统

登录、权限、支付、数据和异常规则无法从截图恢复。

不适合

无人验收的自动上线

视觉相似不代表语义、安全、性能和可维护性合格。

05 / 可扩展场景

下一步不是换一个更大的模型，
而是增加结构和评价。

P0

可测量视觉闭环

像素差、感知距离、布局树、文字和溢出诊断，让“看起来更像”变成可比较证据。

P1

工程化输出

多文件组件、路由、数据模型、设计 token、lint、类型、无障碍和浏览器测试。

P1

结构化输入

读取 Figma 节点、DOM、computed styles 与录屏状态图，减少仅凭像素猜测。

P2

领域视觉 Agent

针对研究展示、数据看板和移动原型提供固定组件、数据契约与验收标准。

06 / 对我们的意义

研究它，不等于需要采用它。

我们的日常输入通常是需求、设计稿、网页或现有代码；孤立截图既低频又缺少结构和业务信息。

现在

归档，不采用

保存实现原理、源码证据、能力边界和否决理由。

偶发任务

使用现有能力

直接让 Codex 看图、实现页面并完成浏览器验证。

连续出现

记录真实需求

统计任务量、人工耗时、失败率、费用和隐私条件。

收益明确

重新评估部署

只有批量收益可量化后，才进行隔离试验和固定评测。

保留的人类职责

  • 事实和来源是否正确
  • 设计是否服务研究问题
  • 许可、隐私与发布边界
  • 浏览器验收是否完整
  • 原型何时值得工程化
