# 交互演示设计契约

- Entry mode：revision-led（在已完成研究页上增加最新热点新闻实战）
- Request revision：3
- Target user and context：希望判断这套 Skill 能否用于热点内容生产的创作者、研究者与内容团队，需要从一条可核实新闻直接看到分镜、提示词、实生成画面、使用场景和商业价值。
- Desired first impression：一条 2026-08-28 的真实热点新闻已经被编译成可执行的手绘短视频生产包；事实层、隐喻层和模型生成层清楚分开。
- Visual ambition：Editorial
- Experience architecture：Editorial Flow
- Visual constraints：沿用上游暖白纸、粗黑线、向日葵黄、钴蓝和番茄红作为识别线索；正文保持研究报告级可读性；不依赖大图、视频或持续动画承载核心信息。
- Information constraints：事实、来源、视觉隐喻和推断分开标注；新闻以中国科学院与新华社公开信息交叉核验；固定上游 commit；完整保留演示输入；仅把实际调用图像模型得到的关键帧标为“实生成”，不把 Prompt 演示描述成已经调用 Flow/Nano Banana 生成完整视频。
- Operation constraints：零前端依赖；静态 HTML/CSS/JavaScript；可部署到现有 GitHub Pages；镜头选择、输出层切换、复制反馈均可用键盘操作。
- State constraints：支持热点来源、七镜头 Prompt 演示、七张实生成关键帧、一条可播放完整参考成片、价值/场景、证据审计、扩展路线；支持镜头选择、隐喻/静帧/运动/风险四种输出状态、视频播放与降级、浅色/深色主题和复制成功反馈。
- Environment constraints：在现有 Research Lab 内运行；源码演示 canonical URL 为 `http://127.0.0.1:8765/projects/hand-drawn-video-prompts-study/demo/`，站点构建后为 `http://127.0.0.1:8000/projects/hand-drawn-video-prompts-study/`；本地 FFmpeg 6.1.3、ffprobe 与 Microsoft Huihui Desktop 中文语音可用于确定性合成；桌面、平板与 390px 手机可用；尊重 reduced-motion。
- Primary journey：直接播放本案例完整参考成片 → 检查七个镜头如何对应口播与 Prompt → 核对新闻来源和事实/隐喻分层 → 理解“AI 生图 + 代码运动/文字/音频合成”的真实边界 → 判断采用和扩展路线。
- User-defined phases：完善一个完整案例；看到可播放最终效果；保留生成方法、事实边界与复现能力；完成媒体和浏览器验证。
- Required artifacts：七张项目内关键帧、中文旁白、字幕文件、可复现媒体合成脚本、带声音与字幕的竖屏 MP4、页面内本案例播放器、媒体审计和更新后的浏览器证据。
- Autonomy authorization：用户明确要求“完善一个案例看到效果，请继续”；允许补齐图片资产、生成本地旁白和字幕、执行媒体合成并更新页面。
- User-decision boundary：实际调用 Flow/Nano Banana、购买外部服务、发布线上站点或修改上游仓库不在本次授权内。
- Observable completion criteria：新闻日期、事实与来源可追溯；七个镜头各有独立实生成关键帧；MP4 包含七段视觉、中文旁白、准确中文关键词/字幕与来源标签，H.264/AAC、9:16 且可由 ffprobe 检查；页面把本案例成片作为主要视频并保留无视频降级文字；自动检查通过；页面在三类视口、双主题、键盘和错误降级路径下可用；仓库校验和站点构建通过。

## 设计方向

| 决策 | 方向 | 可观察约束 | 验收标准 |
| --- | --- | --- | --- |
| 信息层级 | 结论先行，演示居中，证据与路线随后 | 首屏只有一个主判断和四个量化事实 | 不阅读长文也能识别“Prompt 编译器，不是生成引擎” |
| 类型角色 | 中文无衬线正文 + 等宽 Prompt | Prompt 与研究解释有明显角色差异 | 长 Prompt 可读、可滚动、不会撑破布局 |
| 色彩 | 暖纸底 + 黑线 + 黄蓝红语义色 | 颜色不作为唯一状态标识 | 浅色与深色均保持清晰层级 |
| 材质与深度 | 纸张感、实线边框、轻微错位阴影 | 不使用高成本滤镜承载信息 | 关闭图片/动画仍完成主旅程 |
| 响应式 | 桌面双栏，窄屏单栏 | 390px 无横向页面滚动 | 镜头和输出控件始终可达 |
| 动效 | 仅用于状态切换与复制反馈 | reduced-motion 下取消非必要过渡 | 信息不依赖动画出现 |

## 修订 4：案例接入与效果差距优化

- Entry mode：revision-led（把本项目 MiniMax 成片作为一级案例接入，并针对与上游样片的可见差距做一轮优化）
- Request revision：4
- Desired first impression：用户可以在同一视区直接播放“本案例”和“上游参考”，并立刻知道两者分别使用了什么生成链路、为什么动态质量不同。
- Primary journey：播放本案例 → 与上游样例并排比较 → 阅读可观察差距与根因 → 理解代码可优化部分和视频模型上限。
- Visual constraints：沿用现有编辑型研究页；比较区不暗示等价实验；每个视频都显示来源、运动方式和可复现边界。
- Operation constraints：不新增前端依赖；本轮不安装或调用外部付费视频模型；MiniMax 旁白复用已生成的本地音频，不产生新的 TTS 请求。
- State constraints：桌面双视频对照、窄屏单列；两个播放器独立可控；无媒体时仍保留方法与下载入口；尊重 reduced-motion。
- Autonomy authorization：用户明确要求“把我们的示例进行接入”并询问能否优化，授权对现有案例、合成脚本、页面和验证记录做可逆修改。
- User-decision boundary：真正调用 Flow、Veo、Runway、Hailuo 等付费图生视频服务，或把改动提交到上游仓库，需要另行授权与相应服务能力。
- Observable completion criteria：本案例和上游参考在同一比较区可播放且标签真实；本案例前 2.75–3.75 秒按每镜头语义区域分阶段装配，而非 1.15 秒内完成；最后至少 0.8 秒稳定持有终态；媒体元数据记录新的代码运动方式；桌面、平板、390px、主题、键盘、媒体降级与仓库审计通过。
