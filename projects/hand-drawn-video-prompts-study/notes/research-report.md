# Hand-Drawn Video Prompts 研究报告

## 一句话结论

`hand-drawn-video-prompts` 是一个聚焦明确、可以立即辅助创作的 **Prompt 编译型 Agent Skill**：它把中文口播转换为语义分镜、视觉隐喻、静帧 Prompt、图生视频 Prompt 和实体准确性提醒。它不是图像/视频模型，也不是独立的自动成片程序。

它当前最成熟的部分是创作 SOP 和约束设计；最薄弱的部分是规则单一来源、结构化接口、自动评测和外部工具编排。因此，直接使用适合单次提效，Fork 定制适合固定栏目，规模化生产仍需补齐工程层。

本项目已经把“方法是否能进入最终视频”验证到闭环：热点新闻路线以 7 张关键帧 + 代码运动形成 41 秒低成本基线；单图 I2V 路线验证 6 秒对象级运动与构图重绘风险；首尾帧 I2V 路线则用 10 张 FIRST/LAST、5 条状态匹配 Prompt、5 条真实视频模型结果、MiniMax 温润男声和确定性后期形成 30.000 秒最终成片。由此可见，最终质量来自 **Skill + 图像/视频模型 + TTS + 后期代码** 的协作，不能单独归因给 Skill。

| 层 | 本项目实际职责 | 已验证结果 |
| --- | --- | --- |
| Prompt Skill | 文案分镜、视觉隐喻、首尾状态、运动约束、事实边界 | 7 镜头新闻包；5 镜头 Agent 生产合同 |
| 图像/视频模型 | 关键帧和对象级中间运动 | 7 张新闻帧；10 张配对帧；5/5 I2V 镜头 |
| MiniMax TTS | 逐镜文字转语音与时长适配 | `speech-2.8-hd` 温润男声，30.000 秒 |
| 确定性代码 | 媒体核验、裁切、规格、字幕、响度和组装 | 1080×1920 / 24fps / H.264/AAC 最终 MP4 |

## 研究问题与判断标准

研究问题：该 Skill 能否稳定地把中文口播转为可执行、风格一致且风险分层的竖屏短视频提示词？它的能力边界与扩展价值是什么？

判断分成四层：

1. **转换完整性**：新文稿是否得到合理时长、单一含义的镜头，以及自包含的双 Prompt。
2. **约束一致性**：每条输出是否重复比例、背景、线条、配色、构图和运动禁止项。
3. **准确性分层**：公司、日期、数字、Logo、长文本是否被路由到参考图或确定性后期。
4. **端到端边界**：仓库本身是否包含模型调用、生成服务、时间线、导出、测试与失败重试。

会推翻当前判断的证据包括：仓库存在未被发现的可执行生成器；新文稿无法按当前规则形成完整 Prompt；或上游媒体可以证明精确色号、跨镜头一致性和全过程可复现。

## 能力地图

### 直接提供的能力

1. 将中文口播按观点、因果、案例和结论切分为 4–6 秒语义镜头。
2. 给每个镜头寻找“一秒可读”的视觉隐喻。
3. 输出独立完整的英文静帧 Prompt 与图生视频 Prompt。
4. 固定 9:16、`#F8F6EF`、粗黑线和黄/蓝/红配色，预留字幕区。
5. 使用锁定镜头、纸片滑入、轻微弹跳和尾帧保持来限制复杂运动。
6. 将国旗、Logo、公司名、公众人物、数字和长文本划入准确性风险层。
7. 描述自动成片的顺序与交付边界。

### 依赖宿主提供的能力

- 大语言模型的中文理解与视觉隐喻生成。
- Flow、Nano Banana 或其他图像/视频生成能力。
- TTS、转录、字幕、时间线和 MP4 导出。
- 异步任务等待、失败重试、素材存储与项目管理。

### 没有直接提供的能力

- Flow / Nano Banana API 或连接器实现。
- 本地模型、模型权重、训练或推理代码。
- 统一 JSON Schema、CLI 或服务接口。
- 自动化质量评测、回归测试、成本记录和版本管理。
- 对背景精确色值、人物一致性和中文文字准确率的结果保证。

## 工作原理

```text
中文口播
  → 宿主大模型做语义分镜
  → Skill 匹配视觉隐喻并注入重复约束
  → 静帧 Prompt + 运动 Prompt
  → 外部生成模型产出概率性画面
  → 后期工具叠加确定性文字、Logo、数字与字幕
```

### 语义编译

Skill 没有新的分词或镜头算法。它通过自然语言规则要求宿主模型识别观点转折、因果和结论，并把抽象关系翻译成追逐、天平、裂缝、放大镜等物体关系。

### 约束冗余

每条 Prompt 重复画幅、色号、线条、色板、物件数量、留白和禁止项。冗余不是浪费，而是因为单条 Prompt 可能被独立复制，不能依赖“同上”。它能降低随机漂移，但不能构成模型层的一致性保证。

### 运动降维

运动 Prompt 把复杂角色动画降为平面纸片组装：空白首帧、物件依次滑入、刚性纸片弹跳、固定镜头、禁止视差和口型，并在最后约 0.8 秒回到完成静帧。这在创意上更克制，但更容易维持尾帧构图。

### 概率/确定性分层

隐喻、动作和插画交给生成模型；Logo、国旗、精确数字、日期、公司名、长文本和字幕交给参考图或后期图层。这是仓库中最值得复用的通用设计原则。

## 最新热点新闻实战

### 选题与来源

案例选择的是 2026 年 8 月 28 日公布的“我国首次在轨验证地月双向高速激光通信能力”。截至本案例制作时间 2026 年 8 月 29 日，它属于近 48 小时内兼具权威信源、重大科技意义、公众兴趣和强视觉隐喻空间的热点之一。

事实由两条公开来源交叉核验：

- [中国科学院：我国首次实现地月双向高速激光通信](https://www.cas.cn/cm/202608/t20260827_5119119.shtml)，2026-08-27。
- [新华网：我国首次在轨验证地月双向高速激光通信能力](https://www.xinhuanet.com/20260828/2846f43524b94d66bb78c7271d7e9466/c.html)，2026-08-28。

保留的事实包括：超过 40 万公里、首次在轨验证、上行 1.25Mbps、下行 100Mbps、极弱光子探测，以及 8K 月面图像从传统 5Mbps 微波链路约 4–5 分钟缩短到约 12 秒的公开对比。

### 七镜头编译结果

Skill 规则把约 41 秒口播拆为 7 个镜头：

| 镜头 | 核心意思 | 时长 | 视觉隐喻 | 风险处理 |
| --- | --- | ---: | --- | --- |
| 01 | 地月双向链路被打通 | 6s | 地球与月球之间点亮纸带桥 | 日期、距离与“首次”留在字幕 |
| 02 | 运动中瞄准极难 | 6s | 蓝色光束穿过月球旁移动针孔 | “万里穿针”明确标为比喻 |
| 03 | 返回信号只有少量光子 | 6s | 从噪声海洋里捞出光点 | 画面光点数量不作为事实 |
| 04 | 三项技术共同解决难题 | 6s | 瞄准镜、漏斗和编码齿轮三道门 | 两项速率由确定性数据层呈现 |
| 05 | 8K 图像回传显著缩短 | 6s | 长日历跑道与短秒表跑道 | 8K、速率和时间均留在字幕 |
| 06 | 服务未来探月任务 | 6s | 月面数据小车沿光路驶回地球 | 明确是未来用途，不描述为已建成 |
| 07 | 探索价值取决于数据闭环 | 5s | 火箭牵着数据卷轴返回地球 | 标为本案例编辑观点，不冒充原话 |

每个镜头都包含完整静帧 Prompt、运动 Prompt、隐喻和实体风险。自动审计对七镜头执行 28 项 Prompt 合约检查，并另做新闻来源、时效、关键事实和观点分层检查。完整输入与双 Prompt 位于 [`data/demo-case.json`](../data/demo-case.json)。

### 实生成关键帧与参考成片

本次对七个镜头分别实际调用内置图像模型，得到 7 张 `941 × 1672` 的无文字手绘关键帧。图片模型负责隐喻画面；中文关键词、事实字幕和来源由确定性代码叠加。这样既验证了 Prompt 的视觉可读性，也避免让概率模型负责准确中文与数字。

在没有 Flow/Veo 连接器的条件下，本项目用 FFmpeg 按每镜头的主体分布设置 3–4 个语义区域，交替方向滑入并做克制回弹，以 10fps 动作节拍输出 20fps 视频；MiniMax Speech 2.8 HD 新闻女声负责逐镜旁白，代码加入硬字幕与来源标签。最终得到 `1080×1920`、H.264/AAC、41.02 秒的可播放参考成片。它验证的是“新闻 → 可执行生产包 → 七张关键帧 → 确定性编排 → 成片”的链路；不代表原生视频模型的自然动态能力。

### 为什么本案例仍不如上游样片自然

逐秒接触表显示，差距首先来自运动资产，而不是静帧 Prompt：上游 Demo 722 将奖杯、分析师、放大镜和电表作为语义对象按口播顺序加入，并包含观察、称重、推动等谓词对应动作；本项目只有每镜头一张完成态 PNG，代码只能控制整块图像区域的出现时机，不能让人物真正操作物体。

第二个差距是跨镜头一致性。上游反复使用同一分析师角色；本项目七张画面独立生成，没有角色参考图、固定 seed 或共享对象资产，因此人物、线条密度和造型会有轻微漂移。第三个差距是生成链路：41 秒新闻案例没有调用视频模型，因而不会获得模型补间、局部形变和对象内部运动。

本轮先试验了四等分纸片，逐秒接触表发现它会在中间态切断月球和地球，因此没有作为最终方案。最终版本把旧版约 1.15 秒内完成的三段滑入，改为每镜头自定义的 3–4 个语义区域，约 2.75–3.75 秒完成装配，并增加轻微回弹和末段稳定持有。这能改善信息密度和旁白同步，但只能缩小节奏差距。要接近上游，需要二选一：输出人物、道具、光束等透明语义图层后由代码驱动，或者使用空白首帧与完成末帧调用图生视频模型，再由确定性后期叠加中文、数字、字幕和音频。

### 新主题真实图生视频实验

为了直接验证最后一公里，本研究新增“AI Agent 把混乱任务整理成执行流程”单镜头。先用内置图像模型生成 `941×1672` 完成构图，再由用户在外部平台以单图首帧模式生成 6.08 秒 MP4。平台与具体模型参数没有随文件提供，因此不猜测模型名称，也不把结果用于跨模型排名。

媒体审计确认视频为 H.264/AAC、`496×864`、24fps。逐秒接触表显示：散乱卡片连续进入蓝色机器，红色阻塞符号消失，黄色卷纸随后展开为五项清单，人物表情也随过程变化。这证明运动 Prompt 中的语义谓词可以被视频模型转换成对象内部动作，而不只是整块画面滑入。

代价也很明确：输出重新绘制了机器比例、人物姿态、箭头路径、卡片数量和最终布局，没有逐像素保持输入完成图。对“解释动作”而言，这是提升；对品牌角色、严格版式和跨镜头一致性而言，它仍需要首尾帧、主体参考、较低创意度或后期确定性图层。该实验只有一个 6 秒镜头；完整 30 秒成片仍应拆成约 5 个独立镜头生成后再配音、加字幕和组装。

为把这条建议落到可执行层，本研究继续补出 5 镜头/30 秒生产包。镜头分别表达任务洪水、统一收集、识别阻塞、编排流程和执行闭环；五个镜头最终形成 10 张 `941×1672` FIRST/LAST 配对帧，沿用同一人物、蓝色机器、纸张纹理和四色视觉语法。每个运动 Prompt 都明确声明首帧是精确起点、尾帧是精确终点，只允许插值两帧之间可观察的对象变化，并使用锁定正面机位、分段动作时间、刚性纸片运动、保形约束和独立 `No audio.` 禁止项。MiniMax 对五段文案分别生成 4.68–6.37 秒原始语音，经逐镜轻微变速或补齐后得到五段 6 秒 AAC，合并时长为 30.000 秒；动态响度归一化后约为 −16.39 LUFS、−1.41 dBTP。

### 五镜头首尾帧最终结果

用户随后回传按 01–05 命名的五条外部生成结果。源文件技术参数一致：`768×1344`、24fps、6.583 秒、H.264/YUV420P，并各带 32kHz 双声道 AAC。0.10 秒与 5.95 秒抽帧分别接近合同 FIRST/LAST；3.00 秒中间态也能观察到与谓词相符的过程：任务卡散开、卡片进入漏斗、放大镜移动到阻塞、散乱任务转成黄色工作流、检查卡进入结果托盘。这说明首尾帧模式在本案例中既保住了角色和构图锚点，也提供了单图模式缺失的对象级过程运动。

本地后期没有伪造这些中间运动，只执行确定性处理：保留源文件归档，裁取前 6.000 秒，剥离平台音轨，统一为 `1080×1920`、24fps、H.264/YUV420P；五条分镜拼接后加入 MiniMax `Chinese (Mandarin)_Gentleman` 温润男声（`speech-2.8-hd`、`calm`、语速 `0.98`）和两行 ASS 硬字幕，得到 30.000 秒 H.264/AAC 最终成片。第一次直接烧录 SRT 时，中文长句未自动换行并横向溢出；改为人工断句的两行 ASS 后通过 1080×1920 抽帧检查。历史镜头 04 单图实验继续保留，但没有计入 5/5，也没有混入最终视频；被替换的新闻女声已单独归档，可回退但不再作为默认交付。

## 发现的规则漂移

### 1. 视觉组数量

当前 `SKILL.md` 要求 2–4 个主要视觉组，旧 `output-example.md` 仍出现 3–5 组。多出来的一组可能使手机端密度上升。

### 2. 人物比例

当前规则明确禁止巨头小身；旧公开输出仍要求 large head and tiny body。仓库的参考图也比当前文字规则更接近传统大头 Q 版。

### 3. 中文关键词位置

提示词模式默认把短关键词写入生成画面；自动成片工作流又要求所有关键词只作为后期文字层。两者可以解释为模式差异，但字段仍混用“画面关键词”和“后期关键词”，容易让执行器选错策略。

### 4. 空白首帧与固定文字

运动规则同时要求 First Frame 完全空白，以及关键词在镜头中固定、清晰、不变化。若关键词属于完成静帧，它必然需要在空白首帧之后出现；若从第一帧就存在，首帧又不再完全空白。需要明确选择：文字作为生成元素最后出现，或作为独立确定性叠加层全程固定。

这些问题不是不可修复的模型缺陷，而是缺少单一规则来源和自动回归检查造成的文档版本漂移。

## 使用场景

### 适合

- 科技与财经热点解读：把技术难点、因果关系和数字变化转成一秒可读的隐喻。
- 知识科普和课程短视频：按 4–6 秒教学节奏拆解一个连续概念。
- 品牌观点和创始人 IP：固化栏目角色、配色、语气、片头和结尾。
- 抽象观点多、实拍素材少、需要快速补 B-roll 的内容。
- 个人 IP 的固定视觉栏目和批量分镜前期。
- 在人工剪辑或已有媒体工具链中作为中间层。

### 不适合直接使用

- 精确数据可视化、产品 UI、合同条款和品牌规范画面。
- 真人口型、复杂连续表演、电影级运镜和长篇角色叙事。
- 要求 Logo、国旗、中文长句一次生成准确的商业素材。
- 需要无人工复核、高吞吐和严格 SLA 的生产系统。
- 实时灾难、战争和未经核实的爆料；漂亮隐喻可能掩盖事实不确定性，必须加强人工审核。

## 可扩展方向

### P0：新闻事实层与来源 Schema

在现有镜头字段之前增加 source、published_at、accessed_at、verified_facts、editorial_claims 和 corrections，把“信源原话、可核实事实、编辑观点、视觉隐喻”分开存储。热点更新时可以定位受影响镜头，而不是重做整条视频。

### P0：统一规则与结构化输出

将风格、构图、运动和风险规则定义为一份机器可读配置，由此生成 `SKILL.md`、示例和校验规则；输出改为 JSON Schema，字段包含 narration、duration、metaphor、entities、image_prompt、video_prompt、overlay_plan 和 fallback。

### P0：确定性合成层

自动添加中文关键词、Logo、国旗、金额、日期和字幕；生成模型只负责无文字底图。这样可以真正解决准确性和空白首帧/固定文字冲突。

### P1：热点监测与选题评分

在 Skill 前增加选题层：按新鲜度、信源质量、受众相关性、视觉化潜力、误导风险和素材可获得性打分。这样系统追求的是“值得讲且讲得清”，而不是简单复制热搜榜。

### P1：模型适配器

为 Flow、Veo、Kling、Runway、Seedance 等模型分别定义首尾帧、参考图、镜头运动和负面约束，不再假设一套运动语法适用于所有模型。每次生成同时登记 provider、model、seed、输入资产哈希、耗时、费用、失败与重试，避免出现“文件可用但无法归因或横评”的证据缺口。

### P1：自动评测

至少检查：镜头语义覆盖、时长、背景色差、主体安全区、OCR 文字准确率、人物相似度、跨帧闪烁、末帧漂移、失败率、耗时和成本。

### P2：品牌与角色资产

建立品牌色板、线宽、字体、角色 Bible、参考图和允许/禁止物件；按财经、科技、教育等领域建立可检索隐喻库，减少天平、岔路、放大镜的重复。

### P2：生产编排

加入任务队列、单镜头重试、缓存、素材版本、人工审核、时间线和导出记录，才能从 Skill 进入稳定生产。

## 对本 Research Lab 和用户的意义

最直接的价值是把热点生产中反复发生的“读资料—找角度—拆镜头—写双 Prompt—标风险”压缩成一份可检查、可交接的生产包，减少“这句话该画什么”和“怎样把提示词写完整”的前期成本。

对个人创作者，它降低从空白页到第一版分镜的门槛；对团队，它让编辑、设计、生成和后期围绕同一镜头合同协作；对长期栏目，它让角色、色板和领域隐喻成为可以累计的内容资产。

更深的价值是提供了一个 Agent Skill 封装范式：任务足够窄、默认值足够强、输出可直接执行、失败边界明确、参考资料按需加载。它证明个人创作经验可以被编码为可重复调用的工作规范。

但真正可积累的壁垒不是某段 Prompt，而是持续维护的规则单一来源、领域隐喻与品牌资产、跨模型适配数据、自动质量评测与失败样本，以及端到端生产记录。

因此推荐路径是：先直接使用验证题材匹配度；若要做固定栏目，Fork 并替换隐喻、色板与角色；若要产品化，优先补结构化协议、确定性合成和评测，不应先继续堆风格。

## 局限

1. 本研究实际生成了 7 张新闻静帧、10 张 AI Agent FIRST/LAST 配对帧、一条 41 秒代码运动参考成片、一条 6.08 秒历史单图 I2V、5 条首尾帧 I2V 和一条 30 秒最终成片。外部文件缺少平台、模型版本、随机种子、费用和失败重试记录，因此可以验证媒体结果与生产链路，但不能形成严格的模型归因或性价比结论。
2. 仅测试一篇约 41 秒科技热点口播，没有建立跨领域、大样本或连续追踪热点的统计结论。
3. PNG 色彩检测只采样顶部区域，用于验证“精确色号保证”，不是完整前景/背景分割。
4. 对视频的判断基于媒体元数据、FIRST/MID/LAST 抽帧、合同人工核验与浏览器可播放性；尚未逐帧量化闪烁、光流、人物相似度、末帧误差或动作语义得分。
5. 上游仓库会继续变化；所有结论只对应固定 commit `dae2da3`。
