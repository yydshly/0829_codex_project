# 《左耳听风》研究胶囊

## 资料性质

本文件是研究者自写的结构化摘要与合成案例，不包含《左耳听风》专栏原文摘录。其用途是验证 LLM Wiki 能否将安全、可公开的研究输入编译为可追溯、可编辑、可关联的知识页面。

## 来源边界

此前研究使用第三方公开专栏镜像作为受控代理语料。固定快照包含 119 个 Markdown 文件和 162 张图片，但这不能证明已完成对纸质书的逐章分析。该镜像未发现可供本研究依赖的再分发许可，因此本研究不复制、不上传其中的正文。

本页及其派生页面中的事故内容均属于研究者派生材料。任何页面都不应把合成事故写成《左耳听风》中的真实案例，也不应把镜像统计解读为专栏质量评价。

## 主要研究内容

研究胶囊围绕一个合成的慢 SQL 服务雪崩案例，强调以下区分：

- 高频慢 SQL 是直接触发因素，不等于充分根因。
- 重试、连接池耗尽、监控缺口和发布门禁缺失可能共同扩大事故。
- 故障学习应检查技术机制、工程控制、协作流程和组织学习。
- “优化 SQL”可能是必要措施，但不是完整的发现、隔离、恢复和复发验证闭环。
- 未知项和证据缺口必须保留，不能用确定语气补全。

## 证据等级

合成事故内部的因果链是研究者为检验分析方法而编写的内容，不对应真实公司或真实事故。约 27 分钟后确认异常、告警依赖邮件等观察只能作为该合成案例的设定，不能泛化为真实组织或行业的响应时间。
