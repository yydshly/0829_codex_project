# 直接触发与系统根因

## 核心区分

直接触发因素是启动故障过程的事件或条件；系统性根因则是使局部问题能够穿透多层防线并扩大为事故的系统条件。前者回答“故障从什么开始”，后者继续回答“为什么它能够失控”。

在合成慢 SQL 事故中，高频慢 SQL 是直接触发因素。连接池耗尽、重试放大、监控缺口、发布门禁缺失和应急处置缺口共同构成需要继续检查的系统条件。

## 扩散机制

典型扩散链为：

```text
慢查询
→ 资源占用
→ 延迟增加
→ 重试放大
→ 下游压力增加
→ 服务不可用
```

因此，分析不能在找到第一处明显错误后停止，也不能把“优化 SQL”自动视为完整整改。

## 四层检查框架

- 技术机制：索引、查询计划、连接池、重试、限流、熔断和资源隔离。
- 工程控制：性能测试、容量基线、发布门禁、回滚路径和可观测性。
- 协作流程：评审责任、值班响应、升级路径和跨团队同步。
- 组织学习：复盘是否寻找可改变的系统条件，是否把归责误当作治理。

## 责任边界

个人行为可能是事故因素，但个人责任与系统责任并非互斥。系统性分析反对的是用惩罚个人替代可验证的系统治理。
