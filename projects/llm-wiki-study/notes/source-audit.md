## 关键观察

### 1. 摄取是知识编译，不只是文档切块

`src/lib/ingest.ts` 将自动摄取分成分析和页面生成两个阶段。第一阶段识别实体、概念、论证、矛盾和候选页面；第二阶段把结果编码成受格式与安全路径约束的 Wiki 页面。长来源还会进入语义分块与检查点流程。

### 2. 持久 Wiki 是检索前的知识层

生成页保留 `sources[]` 与 `[[wikilink]]`，原始资料和 Wiki 分层保存。关键词、向量和图谱检索建立在这个持久知识层上，因此用户与 Agent 可以共同编辑并重复使用同一知识表示。

### 3. 混合检索不是简单分数相加

`src-tauri/src/commands/search.rs` 使用 RRF 融合关键词与向量排序，并为一跳图谱邻居保留动态配额。图谱相关度还综合直接链接、来源重叠、共同邻居和类型亲和。

### 4. Agent 暴露的是受约束工具面

Agent 可调用 Wiki、来源、Web、图谱、Deep Research、Skills、工作区写入与 Shell 等工具；但 Wiki 写入、产物目录和 Shell 批准都有边界。本地 API 使用 Bearer token，本地 MCP 将其包装为 9 个工具。

### 5. “本地优先”不等于“内容从不离机”

应用、项目文件、Wiki 和索引可以保存在本地；但若使用云端 LLM、Embedding、视觉或搜索服务，内容仍需按对应提供商的数据路径处理。后续隐私研究应明确区分存储面与推理面。

### 6. 原库不是无界面组件，而是桌面产品与多入口体系

固定提交包含 Tauri 桌面应用及完整 React 界面。上游官方截图可见项目知识树、知识图谱、Review / Deep Research、AI Chat、Chrome Clipper 和 Obsidian 兼容路径；本地 API 与 MCP 则承担自动化入口。研究网页因此只做证据导览和实验，不应被理解为原生客户端本身。

## 文档与源码漂移

README 的能力说明仍写有 Deep Research 结果“自动摄取”。固定提交中的 `src/lib/deep-research.ts` 已采用另一条路径：直接生成 `wiki/queries` 页面，验证引用后调用 `embedPage`，并明确避免再次进入来源摄取 / Review 放大流程。

这不是功能缺失，而是实现策略已经变化。展示页将当前能力描述为“直接写页并嵌入”，并把文档差异标为待跟踪项。
