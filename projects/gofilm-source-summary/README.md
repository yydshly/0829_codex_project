# GoFilm 来源机制简析

> GoFilm 是一个调用第三方影视采集 API、整理影片资料与播放地址并提供网页播放的聚合站；其来源机制已被此前的 Moovie 研究覆盖，因此本项目仅做简要归档，后续按需使用。

## 一句话结论

GoFilm 不是片源、通用网页爬虫或独立播放器库。它是一套完整的影视聚合网站：管理员配置兼容 AppleCMS 风格的第三方采集 API，系统在线取得影片资料与外部播放地址，再通过前台播放器直接播放。

其核心取源原理与此前研究的 Moovie 相同，工程实现更简单，但没有提供新的关键研究增量。保留本说明即可，不继续做源码复刻、运行演示或深度实验。

## 它具备什么能力

- 采集影片分类、名称、海报、演员、简介、年份、集数和播放线路。
- 支持一个主源建立影片目录，多个附属源补充播放地址。
- 支持全量采集、按最近若干小时增量采集、定时更新和失败记录重试。
- 提供分类、搜索、详情、多线路选集、HLS 播放和本地观看历史。
- 提供采集源、定时任务、网站配置、轮播、分类和影片管理后台。
- 使用 Redis 暂存采集数据和运行配置，再将长期数据同步到 MySQL。

它不负责视频生产、上传、转码、切片、CDN 或 DRM；通常只是把第三方返回的 `.m3u8` 等播放地址交给浏览器播放器。

## 来源如何实现

GoFilm 不会自动搜索整个互联网，也不是根据任意网页结构抓取内容。来源必须先由管理员配置，主要包含 API 地址、主源或附属源类型、启用状态、返回格式和请求间隔。

系统随后调用类似以下接口：

```text
GET {source_api}?ac=list&pg=1
GET {source_api}?ac=detail&pg=1&h=3
GET {source_api}?ac=detail&ids={vod_id}
```

典型处理链路为：

```text
管理员配置第三方采集 API
        ↓
按分类、页码、更新时间或影片 ID 请求
        ↓
解析 vod_name、vod_douban_id、vod_play_from、vod_play_url 等字段
        ↓
转换为统一影片结构
        ↓
主源保存完整资料，附属源保存额外播放线路
        ↓
优先按外部 ID、其次按标准化片名匹配同一影片
        ↓
Redis 暂存/缓存，MySQL 持久化
        ↓
Gin API 返回线路，Vue + xgplayer 在浏览器中播放
```

因此，项目真正依赖的内容资产不是播放器，而是持续可用、内容合规并能返回正确播放地址的采集来源。

## 部署依赖

Docker 部署会启动四个服务：

| 服务 | 用途 |
| --- | --- |
| Nginx | 前端静态页面与 API 反向代理 |
| GoFilm | Gin 后端、采集和管理接口 |
| MySQL | 影片详情、检索、用户及多源映射 |
| Redis | 缓存、采集暂存、来源配置、任务和登录状态 |

Redis 与 MySQL 在当前实现中都是必需依赖，不能只通过配置删除。使用 Docker Compose 时无需在宿主机单独安装；若要改为 SQLite 或纯内存缓存，需要重写相应存储层。

## 与 Moovie 的差异

| 对比项 | GoFilm | Moovie |
| --- | --- | --- |
| 核心模式 | 提前全量或增量采集，库存优先 | 搜索时并发查询，搜索与编排优先 |
| 目录身份 | 由一个主采集源建立目录 | 豆瓣/TMDB 等元数据与播放来源分离 |
| 多源匹配 | 外部 ID或标准化片名哈希 | 外部 ID、标题、年份、类型、季集和主创综合匹配 |
| 来源质量 | 主要展示可用线路 | 超时、熔断、健康度、首帧与播放结果反馈 |
| 播放失败 | 以手动切换为主 | 限定同一媒体单元自动换源并恢复进度 |
| 数据依赖 | MySQL + Redis | PostgreSQL + 有界进程内缓存 |
| 研究价值 | 简单完整的采集站脚手架 | 更完整的身份、质量和换源参考架构 |

GoFilm 相对 Moovie 的少量增量主要是“主源/附属源”以及“Redis 采集中转后同步 MySQL”的实现方式；来源配置、播放串解析、内容匹配、来源健康度和失败换源等关键问题，我们已经在 Moovie 项目中做过更深入的研究。

## 采用判断

### 可以按需参考

- 需要快速理解 AppleCMS 风格采集 API 时。
- 需要一个 Go + Vue 的自建影视聚合站原型时。
- 需要参考全量初始化、定时增量、主附源存储时。

### 不建议继续投入研究

- 只为研究视频播放器：播放器是常规技术组件。
- 只为研究来源获取：此前 Moovie 研究已经覆盖且更深入。
- 计划直接用于公网或商业运营：现有安全性、可靠性和内容合规能力不足。
- 计划建设长期视频平台：应重新设计来源适配、规范媒体身份、季集映射、来源质量和安全换源闭环。

## 已知边界

- 当前采集核心实际固定走 JSON，XML 类型只有未完成的结构。
- 并发请求共享部分全局响应状态，存在数据竞争和响应串线风险。
- 默认部署包含管理员和数据库默认凭据，且认证密钥固定在源码中，不能原样暴露到公网。
- 项目没有自动化测试和 CI；能够编译不代表采集链路长期稳定。
- MIT 许可只覆盖 GoFilm 代码，不授予第三方影片、海报、元数据或播放地址的内容权利。

## 最终归档结论

```text
研究价值：低
采用方式：后续按需参考，不作为当前技术主线
值得保留：采集 API 参数、vod_* 字段转换、主源/附属源模型
无需继续：播放器、Vue/Gin 页面、MySQL/Redis 常规工程细节
更优参考：此前完成的 Moovie 来源配置、身份匹配、质量评估与失败换源研究
```

本项目不建立上游代码副本、不制作演示站，也不继续追踪功能更新。未来只有在实际需要部署简易聚合站或实现 AppleCMS 适配器时，再重新核验最新代码、来源协议、安全配置和内容授权。
